# Stage 04: Progress Tracker And Handoff Protocol

## 0. Standing rules
- Treat the revised GDD, revised Build Requirements, `docs/DECISIONS.md`, and `PROJECT_STATUS.md` as source of truth. The locked MVP and decisions override older full-game scope.
- Inspect before editing; preserve existing user work; avoid unrelated rewrites.
- Implement, run checks, fix failures, verify acceptance criteria, update the tracker, and write a handoff report.
- Do not claim a test/build/tool ran unless you actually executed it. Mark anything impossible to verify as UNVERIFIED with a reason.
- Keep `Severed_Cursor_Prompt_Pack/` read-only. Never silently weaken/delete tests to get green.
- Ask the owner only for consequential decisions or tasks that cannot be automated safely.

## 1. Role
Technical project manager and automation engineer.

## 2. Context
Stages 00-03 COMPLETE. `PROJECT_STATUS.md` exists from the pack template and has been edited by hand during earlier stages.

## 3. Objective
Make progress tracking robust and machine-checkable so an interrupted session can resume from the tracker alone, and add tools that keep the tracker honest.

## 4. Prerequisites
1. Stage 03 COMPLETE.

## 5. Workspace inspection
1. `PROJECT_STATUS.md`, `RESUME_PROMPT.md`, `docs/handoff/*`, `Severed_Cursor_Prompt_Pack/PROMPT_INDEX.md`.
2. `tools/` layout from stage 02.

## 6. Implementation tasks
1. Review `PROJECT_STATUS.md` structure against the template. Required top-level headings (exact): `Environment`, `Current Stage`, `Stage Table`, `Completed Features`, `Files and Systems Changed`, `Tests (latest run)`, `Known Bugs and Blockers`, `Decisions Made`, `Deferred / Proposed Work`, `Owner Actions and Checkpoints`, `Next Recommended Action`, `Next Prompt Filename`, `Session Log`.
2. Implement `tools/status/status_check.py`: parses `PROJECT_STATUS.md`; verifies all required headings; each stage in the table has a status in {NOT_STARTED, IN_PROGRESS, COMPLETE, PARTIAL, BLOCKED}; the *Next Prompt Filename* exists in `Severed_Cursor_Prompt_Pack/`; no stage is COMPLETE if an earlier required stage is not COMPLETE (use the dependency map in `PROMPT_INDEX.md`, copy it to `tools/status/dependencies.json`); a COMPLETE stage has a handoff file in `docs/handoff/`; checkpoints A-D recorded when due. Exit non-zero with readable messages. Add Python unit tests.
3. Implement `tools/status/update_status.py` with subcommands: `set-stage <id> <STATUS>`, `log <message>`, `record-tests <path to build/test_results.json>` (writes pass/fail counts and timestamp into the *Tests (latest run)* section), `next <filename>`. It must edit only the targeted section and preserve all other text (test with a round-trip fixture).
4. Create `docs/handoff/_TEMPLATE.md` matching the 9-part handoff structure used in every prompt, and `docs/handoff/INDEX.md` listing handoffs (auto-regenerated by `update_status.py index`).
5. Add `tools/status/status_check.py` to `tools/check_all.*`. Update `RESUME_PROMPT.md` if needed so it says: read `PROJECT_STATUS.md`, run `tools/status/status_check.py`, read the last handoff, resume the stage marked IN_PROGRESS or start the *Next Prompt Filename*, never skip.
6. Write `docs/PROCESS.md`: the stage loop, how to resume after interruption, how fix prompts are created when a checkpoint fails (`docs/handoff/fix_<checkpoint>_<n>.md` generated from the owner's bug report using the template in `MANUAL_CHECKPOINTS.md`), and the rule that Cursor never advances with an unmet critical criterion.
7. Update the tracker for stages 00-04 so it is truthful (use `update_status.py`), run all checks, commit.

## 7. Technical constraints
1. Standard-library Python only.
2. Never overwrite the owner's free-text notes in the tracker.
3. Tools must produce clear errors, not stack traces, on bad input.

## 8. Files and outputs
1. `tools/status/{status_check.py,update_status.py,dependencies.json}` and tests
2. `docs/handoff/_TEMPLATE.md`, `INDEX.md`, `docs/PROCESS.md`
3. Updated `PROJECT_STATUS.md`, `RESUME_PROMPT.md`

## 9. Automated tests
1. Python unittest: valid tracker passes; missing heading fails; COMPLETE stage lacking handoff fails; COMPLETE stage with incomplete dependency fails; nonexistent next prompt fails; round-trip edit preserves untouched sections.

## 10. Execution and verification
1. `python3 -m unittest discover -s tools/status` passes.
2. `python3 tools/status/status_check.py` passes on the real tracker.
3. Introduce a deliberate inconsistency, confirm failure, revert.
4. `tools/check_all.sh` exits 0.

## 11. Acceptance criteria
1. Tracker structure validated automatically.
2. A fresh Cursor session using only `RESUME_PROMPT.md` could identify the current stage and next prompt (describe a dry run of this in the handoff).
3. Tracker truthfully reflects stages 00-04.

## 12. Failure handling
If any command, test, import, build, export, or acceptance criterion fails: stop the stage from being marked COMPLETE; capture the exact error and relevant logs; diagnose the smallest root cause; apply the smallest safe fix; add a regression test where applicable; rerun the failed check and relevant suite. If blocked by missing tools or permissions, document exact owner action and mark BLOCKED rather than guessing.

## 13. Handoff report
Write `docs/handoff/04_PROGRESS_TRACKER_AND_HANDOFF_PROTOCOL.md` including: stage result; changed files; actual commands run; test results; acceptance criteria PASS/FAIL/UNVERIFIED with evidence; known bugs/blockers; decisions made; owner action if any; and **Next prompt to execute** with the exact filename. Update `PROJECT_STATUS.md` truthfully.

## 14. Scope guard
1. No gameplay or art work.
2. Do not start stage 05.
3. Do not implement deferred features: online/rollback/matchmaking/ranked, four-player brawl, co-op, spectator, additional roster/arenas/abilities/limbs beyond locked MVP, Death Match, Thunder Strike cinematic, Last Stand, Execution, Legacy, Hall of the Fallen, cosmetic unlocks, Chronicle share card, voice acting, one-handed layouts, modding, monetisation, or paid services. Keep the game free.

**Next prompt to execute:** determine from `PROMPT_INDEX.md` and `PROJECT_STATUS.md`; do not skip prerequisites.

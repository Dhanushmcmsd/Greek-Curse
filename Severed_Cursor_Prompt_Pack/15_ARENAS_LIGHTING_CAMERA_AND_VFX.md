## 6. Implementation tasks
1. Data `data/arenas/<id>.json` (+schema) for `mount_olympus`, `athens_colosseum`, `tartarus_pits`: sim bounds (mm), wall positions, floor friction/none, safe zone rectangle (hazard-free), spawn points, hazard definition (type, schedule from seed, telegraph ticks, active ticks, damage, limb damage, area), palette (Olympus gold/white, Colosseum sand/stone, Tartarus red/black), lighting preset, ambience ids, blood behaviour (`decal_fade_ticks`, `wash_away`), `hazards_default_on`.
2. Sim hazards in `src/sim/sim_hazards.gd`: Mount Olympus **lightning strikes** (marker telegraph >= 90 ticks, then damage + limb damage + char effect modifier flag in a zone), Tartarus **lava vents** (telegraphed periodic eruption zones with damage and small limb chip), Athens Colosseum has **no sim hazard** (visual crowd only; sand hides decals over time). Hazard schedules come from the match seed via `SimRng` so replays are deterministic; hazards must never overlap the safe zone and must be toggleable in `MatchConfig.rules.hazards`. Wall bounce hooks use real arena walls.
3. Blender kits: `tools/blender/lib/arena_kit.py` and `build_arena.py --id <id>` generating floor tiles, walls, columns, steps, braziers, cloud puffs, lava rocks/vents, stands/crowd blocks, banners, props; modular reuse across arenas; budgets from art config; exports `arena_<id>.glb` plus `prop_*.glb` and a manifest. Include skybox-replacement via procedural `Sky`/`WorldEnvironment` (no image textures).
4. Godot `ArenaBuilder` (`src/presentation/arena_builder.gd`): builds the arena scene from data+glb at runtime (floor, walls, props, lights, environment, hazard visuals: lightning marker + bolt, lava vent glow + eruption particles), with collision shapes **not** used for gameplay. Lighting per arena (key light, fill, ambient; shadow quality low/medium switch for performance), distinct colour grading, fog where fitting.
5. Fight camera (`src/presentation/fight_camera.gd`): side-on 2.5D, frames both fighters with data-driven min/max distance, smooth follow (visual only), height offset, FOV, bounds clamp so it never shows beyond arena edges, shake hook with `SettingsHooks`, optional dramatic zoom on sever (small, respecting flash/shake settings).
6. Gore manager (`src/presentation/gore_manager.gd`): consumes sim events; blood droplets (CPUParticles3D pooled), **floor/wall splats as pooled flat quads (or `Decal` nodes only if verified supported in the chosen renderer)** with a hard cap (default 64 floor + 32 wall, data-driven) recycling the oldest; severed-limb debris (the limb model as a cosmetic `RigidBody3D` with lifetime and cap, Godot physics allowed here only); gore chunk pool generated by Blender (`build_gore.py`, 15 chunks in flesh/bone/marble? no - flesh, bone, charred, bronze shrapnel, <=80 tris each) with a global chunk cap (default 24) and lifetime; blood colour variants red/green/golden ichor via palette; gore level Off (sparks/dust only)/Low/Normal/Max scale counts and chunk probability; Colosseum sand fades splats faster; stump blood spray.
7. Hit sparks/dust, shockwave ring, simple lightning flash (respect photosensitivity: when `flash_reduction` is on, replace full-screen flash with a gentle tint), lava glow pulses. All VFX are presentation-only and cost-capped.
8. Tools: `scenes/debug/arena_viewer.tscn` (cycle arenas, toggle hazards, spawn gore stress test), `tools/sim/hazard_replay.gd` (headless hazard determinism run).
9. Tests, previews (arena contact sheets via Blender workbench renders and, if possible, Godot screenshots), ledger, `docs/ARENAS_VFX.md`, commit.

## 7. Technical constraints
1. Gameplay hazards live in the sim, integer, deterministic; their visuals live in presentation.
2. Godot physics only for cosmetic debris.
3. Hard caps on decals/chunks/particles enforced in code and tested.
4. No image textures from external sources; procedural/vertex-colour only.

## 9. Automated tests
1. Arena data schema + semantic validation (safe zone inside bounds, spawns inside bounds and inside safe zone, hazards never overlap safe zone, telegraph >= minimum).
2. Hazard determinism: same seed -> same schedule and same hash; hazards off -> no hazard events.
3. Hazard rule tests: telegraph precedes damage; damage applies once per eruption per fighter; safe zone immunity.
4. Gore caps: spawn 10x the cap, assert live count <= cap; gore level Off spawns no blood/chunks; blood colour variants applied.
5. ArenaBuilder loads each arena headless without errors; camera framing math tests (pure function) incl. clamp.
6. Asset validators on arenas/props/gore.

## 11. Acceptance criteria
1. Three arenas playable from `MatchConfig.arena_id`, each visually distinct with a safe zone.
2. Hazards are telegraphed, deterministic, toggleable, and covered by tests.
3. Gore/VFX budgets enforced and gore levels/blood colours work.
4. Camera frames both fighters in all arenas without leaving bounds.
